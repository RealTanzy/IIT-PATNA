OVERVIEW
------------------------------------------------------------------------
We identified 93 StrategyQA questions where Chain-of-Thought (CoT) and
A* search gave different predictions in the original seed-42 experiment.
To obtain a reliable estimate of each method's true accuracy on this
disagreement set — free from single-run noise — we ran BOTH methods
independently 3 times and applied majority voting (best-of-3).

All 6 runs used the same model (llama3.1:8b via Ollama) with the same
hyperparameters. No prompt changes were made between runs.

EXPERIMENTAL SETUP
------------------------------------------------------------------------
  Dataset        : StrategyQA — 93-question disagreement subset
  Question type  : binary yes/no
  Model          : llama3.1:8b (Ollama, local)
  CoT setup      : single-pass chain-of-thought, temperature 0.3
  A* setup       : beam search, MAX_NODES=15, BRANCH_K=2, MAX_DEPTH=8
                   avg nodes explored — R1:5.4  R2:7.6  R3:7.4

  Run provenance:
    CoT  R1 : original seed-42 run  (42_cot_question_only_results.jsonl)
    CoT  R2 : experiment.py re-run  (cot_results.json)
    CoT  R3 : run3.py re-run        (cot_results_run3.json)
    A*   R1 : original seed-42 run  (Astar_llama3.1_8b_42_..._final.json)
    A*   R2 : experiment.py re-run  (astar_results.json)
    A*   R3 : run3.py re-run        (astar_results_run3.json)

  Majority vote  : 2-of-3 or 3-of-3 wins; ties treated as no-answer
  Zero 3-way ties observed (binary yes/no — ties only on null outputs)

WHY A* UNDERPERFORMS CoT ON THE DISAGREEMENT SET
------------------------------------------------------------------------
  1. HIGH SEARCH VARIANCE
     A* explored 5.4 nodes/question in R1, 7.6 in R2, 7.4 in R3.
     62 of 93 questions saw A* flip its answer at least once across runs.
     More nodes explored does NOT guarantee a better answer — the LLM
     itself generates the reasoning steps, so LLM noise propagates.

  2. SYMMETRIC SEARCH PRESSURE
     The disagreement set contains questions where CoT was systematically
     wrong in R1 (48 questions) and A* was wrong (45 questions). By
     construction, both methods are near the chance boundary (50%) here.
     A*'s multi-step reasoning can amplify early errors rather than
     correct them when the LLM's factual recall is already uncertain.

  3. MAJORITY VOTE HURTS A* MORE THAN CoT
     A* fixed 16 questions but also broke 15 that were originally correct.
     CoT fixed 23 questions while breaking only 13.
     This suggests A*'s run-to-run variance is higher, so the losing
     answer (incorrect) sometimes wins 2-of-3 by random chance.

  4. CONSISTENTLY HARD QUESTIONS
     22 questions were wrong under BOTH methods' majority votes.
     Gold distribution of hard set: 14 'yes', 8 'no'.
     These questions likely require multi-hop factual knowledge that
     llama3.1:8b does not reliably have, making both methods fail.

CONCLUSION
------------------------------------------------------------------------
  CoT wins the majority vote head-to-head: 55/93 (59.1%) vs 49/93 (52.7%)
  — a margin of +6 questions (+6.5%).

  However, this result requires careful interpretation:

  - The single best individual run was CoT R3 (60/93, 64.5%), followed
    by A* R3 (55/93, 59.1%). Both methods improved substantially from R1.

  - A*'s majority accuracy (49/93) is LOWER than its best individual run
    (55/93), showing that its vote distribution is noisy enough that the
    correct answer sometimes loses 2-of-3 by sampling variance.

  - CoT benefits more from majority voting (net +10 vs R1) compared to
    A* (net +1 vs R1), making it a more stable method on this task.

  - The 22 questions neither method can solve suggest a knowledge ceiling
    for llama3.1:8b on StrategyQA's harder multi-hop questions.

  Recommendation: A*'s advantage over CoT observed in full-dataset runs
  does NOT hold on the disagreement set, where both methods are near
  chance. The disagreement set specifically selects questions where
  the methods differ — so neither has a structural advantage here.
  Future work should use higher temperatures or self-consistency (5+ runs)
  to stabilise A*'s search trajectory on ambiguous questions.
